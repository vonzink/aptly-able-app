# Recording location, triggered by Plaud

Approved in conversation: optional Settings switch, off by default; device recording start/stop triggers phone location while connected; stopping, disabling or disconnecting stops location without interrupting audio. Native capture must not depend on a foreground React render. Local-only, no server upload or automatic geocoding. Coordinates belong to actor + recorder serial + session ID, never import time. No promise of capture after force-quit or a missed Bluetooth event.

## Design
- Native iOS Core Location / Android LocationManager managers, separate from the SDK bridge. The SDK forwards confirmed start/resume, pause/stop, disconnect and shutdown to the location manager before delivering JS events.
- Native pending journal persists samples atomically in private, backup-excluded storage. Capture every >=30 seconds, accurate to <=1000 m, sample age <=30 seconds, maximum 600 points/session, five-hour capture limit. Reject future (>5 seconds), stale, invalid and pre-segment points. Each pause/resume or interrupted segment preserves its gap. Pending sessions expire after 30 days, capped at 100; never keep unbounded GPS files.
- Consent stored per account, default false. Context binds authenticated actor and verified ready serial. Native connection loss stops capture; no reconstructing start locations later. New permission grant or enabling during a recording waits for the next confirmed start/resume.
- iOS When In Use supports foreground starts; optional Always permission supports background starts. Background Bluetooth/location delivery still needs real-device acceptance. Android arms an explicit foreground location service while the app is visible, with an ongoing notification; only samples after recorder start. No ACCESS_BACKGROUND_LOCATION requested. If the service cannot arm, report background-not-ready; never work around OS restrictions.
- JS attaches validated complete or interrupted GPS coverage only to durable audio imported through the existing idle-state transfer gate. Both recording and pause block transfer; connection/session changes invalidate it before import. "Interrupted" describes partial GPS coverage, not hardware finality: recordings stopped offline have no final stop callback. Recording/paused location journals remain ineligible. Only acknowledge/purge pending native points after metadata save. Location read errors never block audio imports. Record deletion and account deletion also purge pending location. Independent Remove location action; no location in audio exports or transcription uploads.
- UI: Settings switch + plain-language disclosure before enable + permission/background readiness + recovery. Recording location card shows first/last point, time/accuracy, partial/missing status, and explicit Open in Maps and Remove location.

## Verification and boundaries
Unit checks cover source ownership, invalid data, gaps, consent/context races, rejected enable, failure recovery, persistence and deletion. Compile native code on both platforms. Hardware acceptance includes button/lock/disconnect/pause/denial cases. No deployment, physical pairing, permission grants or store submission in this implementation. Existing app identity and release readiness gates stay intact.
