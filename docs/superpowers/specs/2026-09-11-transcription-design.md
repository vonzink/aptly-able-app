# Imported audio to automatic Plaud transcript

The user approved continuing the proposed import → upload → automatic transcript milestone. This adds a backend subsystem to the existing app. Production sign-in/security, hardware integration, summaries and deployment remain outside this slice. Preserve current safeguards and all local recording features.

Use the existing API/Postgres plus backend disk staging and Plaud managed upload. The alternative of provisioning S3 first delays functional proof; the alternative of exposing provider upload authentication to clients complicates platform behavior. Backend staging behind an audio-storage port permits S3 replacement later. This is local server persistence, not a deployed cloud backup or cross-device library.

A detail-screen action explicitly uploads a chosen local recording for automatic transcription. Existing local development sign-in is reused. Capability/status queries describe absent provider credentials honestly; no generated transcript appears without a provider result. Imported transcripts remain separate and unchanged. Completed generated transcripts display alongside the imported transcript, use real timestamps for playback and remain in Postgres across process/browser restarts.

Registration uses the local recording UUID and authenticated owner. Matching retries return the existing row; conflicting file name/byte count fails. Title is display metadata: a local rename does not change audio identity or overwrite the initial server label. Server rename/library synchronization is later work. Upload streams bounded bytes into a unique staging file, checks length and SHA-256, then atomically publishes the verified file and queues the database record. File paths, provider tokens, signed URLs and upstream errors never enter public contracts. Deleting the existing local copy does not delete server data; update removal copy to state that distinction.

A single durable worker coordinator uses a Postgres advisory lock across each provider operation. It claims a queued upload, uploads to Plaud, checkpoints submitting before the non-idempotent transcription POST, stores the returned task ID, then polls using that ID. Restart during upload can restart the upload; restart/ambiguous failure during submission becomes submission_uncertain and never silently resubmits. Poll transport errors retry with bounded backoff; terminal failure and revoked statuses stop. Manual retry starts a new attempt only from terminal failure or explicit uncertain-submission confirmation. No blind automatic POST retries. Polling has a 24-hour deadline; all HTTP calls have timeouts and shutdown releases the worker.

Provider interface: uploadAudio({userId,path,fileType,sizeBytes}):Promise<{downloadUrl:string}>; submit(downloadUrl):Promise<string>; poll(taskId):Promise<{status:'pending'}|{status:'failed'}|{status:'complete',transcript:GeneratedTranscript}>. API credentials remain backend-only. PLAUD_CLIENT_ID, PLAUD_CLIENT_SECRET and PLAUD_API_KEY must all be present to enable provider work. No credential values were found in current API configuration.

Public API: GET /v1/transcription/capabilities (public availability); POST /v1/recordings register {id,title,fileName,sizeBytes}; GET /v1/recordings/:id; POST /v1/recordings/:id/audio raw application/octet-stream; POST /v1/recordings/:id/retry {acknowledgeDuplicateRisk:boolean}. All except capabilities require the existing actor. Response fields: id,title,fileName,sizeBytes,status,attempt,createdAt,updatedAt,errorCode,transcript. Status: awaiting_upload,queued,uploading,submitting,transcribing,complete,failed,submission_uncertain. GeneratedTranscript: text,segments,durationSeconds,language (nullable). Max audio 250 MiB; TXT/SRT/VTT importer is unchanged.

Verification: real temporary filesystem and isolated Postgres; protocol fake HTTP at the provider transport boundary for multipart bytes/ETags/MD5/auth/normalization; app controller and request boundary tests; browser missing-config path and an isolated end-to-end fake-provider harness explicitly labeled test data; workspace checks and iOS/Android/web exports. Live Plaud and physical phone claims require actual credentials/hardware evidence.
