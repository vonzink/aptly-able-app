# Automatic recording sync

Recordings from the paired NotePin S must appear in Aptly Able automatically. The approved current scope is direct device receipt with a **stub for the future server API integration**. Automatic upload, transcription and Aptly Able AI are the eventual workflow; none are activated for device recordings in this slice. Outside audio import remains optional. MCP is not part of device transfer.

## Current implementation slice

- An app-level transfer coordinator uses the existing SDK file-list, recording-stop and MP3-export methods. It starts only after the assigned recorder's complete connection handshake. Navigation does not own the coordinator.
- Transfer complete recordings sequentially while the app is active. Refresh after a recording stops, on reconnect, and periodically while connected. Keep recorder originals. Ignore files from a different serial and stale callbacks after connection/account changes.
- Persist recorder source identity together with the local audio. Deduplicate repeated file lists and reconnects against saved source identity, including owner, serial, session and source size. A growing session is a distinct source revision; do not overwrite previously uploaded audio. A deletion receipt, scoped to owner, serial and session (not size), prevents user-deleted recordings from automatically returning. Clearing temporary audio retains the library entry, so normal sync also skips it until the user explicitly requests audio.
- Define a separate `RecordingServerPort` for upload and processing/transcript retrieval. Its default adapter explicitly reports `configured: false` and rejects method calls; it must not make HTTP calls, return invented upload receipts or generate mock transcripts. Durable local recording/source metadata is the starting point for a future delivery queue.
- Synced Plaud recordings show that server upload and transcription are pending integration. The existing manual transcription feature remains available for outside imports; do not trigger it for device recordings. This slice makes no API/server/database changes.
- The UI distinguishes recorder transfer, local audio and transfer failures. Outside file import is secondary; no instruction to use the Plaud consumer app.

## Boundaries and limitations

The app keeps durable source metadata in Documents and new Plaud audio in a separate, capped 100 MiB cache. Old unleased cache audio is removed to make room; an open player holds a lease. If a received file cannot fit, its metadata is retained without a permanent audio copy. The user can load audio again from the matching connected recorder or choose Download to phone to retain it in the app until deletion. Explicit downloads, outside imports and pre-existing permanent audio are not automatically evicted. Clear temporary audio preserves library entries and transcripts. Small deletion receipts remain after removal; recorder originals are never deleted. The app's private recording store owns this storage policy. A future implementation can reuse this repository's API, filesystem storage and Postgres or implement private S3 storage behind the server interface. No data is sent to a new server in this slice. Hosted runtime, upload queue, automatic transcription and AI processing remain later integrations. The existing 250 MiB audio limit remains. Background transfer and automatic reconnection after app termination require separate iOS/Android work.

The installed SDK bridge has no export-cancellation method. Only one export may run at a time. A stalled native export reports an error; do not start another export until the first native promise settles. A stuck native operation may require reopening the app. Never treat dispatch or progress as saved audio. Failed saves expose their underlying error instead of assuming a full phone; periodic transfer retries stop on errors until a new request or connection event. Temporary SDK export audio is removed when the export promise settles, including after rejected imports. SDK working files can temporarily consume additional space during transfer; the 100 MiB limit applies to retained app audio cache.

## Verification

Test completed-transfer persistence, duplicate lists and controller recreation, exact recorder matching, recording start/stop, one export at a time, sign-out/background invalidation, late completion and error recovery. Confirm the unconfigured server adapter cannot report a successful upload or transcript. Run workspace checks and export all platform bundles. Physical transfer/playback is a separate acceptance step; Android native compilation remains blocked by its missing vendor AAR.
